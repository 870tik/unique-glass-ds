# 02 — Layout: レイヤー規範とレイアウトルール

根拠は [00-philosophy.md](00-philosophy.md) 公理6。既存 glassmorphism キットに
一番欠けているのがこの章である。ここを守らない実装は、このシステムの実装ではない。

## 二層モデル

```
┌─ 機能レイヤー（ガラス）─ ナビ・タブバー・ボタン・モーダル・操作系
│    …コンテンツの上に浮かび、下をスクロールが通り抜ける
└─ コンテンツ層（不透明）─ 本文・画像・カードの中身・アプリ背景
     …通常のマテリアル。ガラスにしない
```

### 禁則（Do / Don't）

- **Don't**: コンテンツ層にガラスを使う（読むもの・見るものはガラスにならない）
  - 例外: スライダー・トグル等の操作子は**操作中だけ**一時ガラス化してよい
    （`.lg-field` の focus 挙動が実装例）
- **Don't**: ガラスの上にガラスを積む。ガラス上の分離は塗り（`color-mix` +
  `--lg-ink`）と透明度で行う。`.lg-nav-pill` が実装例
- **Don't**: 1画面に多数のガラスを浮かべる。**ガラスの使用予算は「1ビューポートに
  独立したガラス面 3 枚まで」を目安**とする（ナビ1 + 浮遊操作系1 + モーダル等の
  一時面1）。ボタン群など同一コンテナ内の集合は1枚と数える
  - アプリ（SaaS 等）の場合: サイドバー + トップバーの**恒常クロームは合わせて
    1枚**と数える（lg-shell）。メニュー・コマンドパレット・トースト・ツールチップ
    等の**一時オーバーレイは予算外**（同時に出るのは通常1枚であり、閉じれば消える）。
    恒常的に浮かぶガラスが増えることだけが予算違反
- **Do**: 迷ったらガラスにしない。希少性が価値（透明度は可読性の負債であり、
  予算を超えた分は必ず可読性で支払うことになる）

## クロームの2型（サイト型 / アプリ型）

黒ナビ（グローバルヘッダー / topbar）とサイドナビの主従は、ページの主活動で決める。
**読む・回遊するなら A、タスクを操作するなら B。**

| | A. サイト型クローム | B. アプリ型クローム（SaaS） |
|---|---|---|
| 主役 | 横断ナビ（ページ間の回遊） | サイドナビ（セクション切替・全高 sticky） |
| 黒ナビ | 全幅・最上部。ブランド + 横断リンク | サイドナビの右・コンテンツ列の最上部に sticky。検索・アクション・ユーザー（ブランドは置かない） |
| ブランド | ヘッダー左 | サイドバー上部 |
| 実装 | ページ固有 or 共有ヘッダー | `.lg-shell`（sidebar / topbar / content の grid） |

- **二重クローム禁止**: B の上にさらに全幅ヘッダーを重ねない（ガラス予算と主従の崩壊）。
  ドキュメントサイトにアプリのデモを埋める場合は iframe の枠で境界を作る
  （枠の外 = A、枠の中 = B。本ショーケースのデモページが実例）
- ブランドの所在は型で確定し、移動しない

## SaaS / アプリ画面での二層モデル

密度の高いプロダクト UI では、**読む要素が主役**であり、ガラスは脇役に回る:

| 要素 | 層 | 部品 |
|---|---|---|
| サイドバー・トップバー | ガラス（恒常クローム1枚） | lg-shell / lg-sidebar / lg-topbar |
| メニュー・⌘K・トースト・ツールチップ | ガラス（一時オーバーレイ） | lg-menu / lg-command / lg-toast / lg-tooltip |
| テーブル・統計タイル・フォーム・本文 | コンテンツ層（不透明） | lg-table / lg-stat / lg-panel / lg-form-row |
| スイッチ・スライダー等の操作子 | 通常は塗り、**操作中だけガラス化** | lg-switch / lg-slider ほか |

データテーブルをガラスにしたくなったら、それは公理6違反のサイン。
ガラスの下をコンテンツがスクロールで通り抜ける（シェル）か、コンテンツの上に
一時的に浮かぶ（オーバーレイ）か、どちらでもないガラスは疑うこと。

## 画面レイアウト型（.lg-layout-*）

Web サービスの画面類型は7つの型で組む。全型 SP 対応
（md 900: サイドバーがオフキャンバス化・split/settings が1カラム化、
sm 640: テーブルがカード化・アクションバーが全幅化）。
生きた実証は [showcase/screens.html](../showcase/screens.html)。

| 画面型 | 骨格 | 要点 |
|---|---|---|
| 基本（Dashboard） | `.lg-page` + `.lg-page-header` + `.lg-grid-stats` + `.lg-split` | shell 内の標準形 |
| 一覧（List） | `.lg-toolbar` + `.lg-table--responsive` + `.lg-pagination` | td に `data-th` を書く（SP カード化のラベル） |
| 閲覧（Detail） | `.lg-page-header`（径路+見出し+actions）+ `.lg-split--aside-first` | メタは aside。SP では**メタが本文より先頭**（Total 等の第一情報を上に） |
| 編集（Edit） | `.lg-layout-form`（max 640px・**シェル内は左軸**）+ `.lg-actionbar` | アクションバーは sticky なガラス1枚（予算内）。中央軸は focus のみ |
| 新規（Create） | `.lg-layout-focus` + `.lg-stepper` | シェルを外した集中型。戻る導線必須 |
| 設定（Settings） | `.lg-layout-settings` + `.lg-subnav` | サブナビは塗り。md↓で横スクロールタブ |
| 認証（Auth) | `.lg-layout-auth` + `.lg-auth-card` | 中央1カラム。カード内の入力は fill 相 |

共通部材: `.lg-page`（最大幅 1200 + 余白）/ `.lg-page-header` / `.lg-toolbar` /
`.lg-grid-stats` / `.lg-split`（本文 + 320px サイド。`--aside-first` で SP 時メタ先頭）/
`.lg-actionbar`。

余白のリズム: セクション間は `--lg-layout-section-gap`（= 3xl 32）。ただし
**toolbar は直下のコンテンツの操作系**なので、toolbar→コンテンツ間だけ lg(16) に
自動で詰まり「header ‖ (toolbar+コンテンツ)」のグルーピングを作る。
見出しの階層: **h1 は全画面 `.lg-type-display`**（1画面1回）。title は h2 に使う。

## 可読性予算

ガラスを置いてよいかは「その要素は何秒読まれるか」で判断する:

| 読まれ方 | ガラス | 根拠 |
|---|---|---|
| 一瞥（アイコン・ラベル1語） | ○ | 予算内 |
| 短文（ボタン・タブ・通知1行） | ○ Regular | 適応が守る |
| 数行（モーダルの説明文） | △ Regular + 濃い face | 背景次第 |
| 本文・長文 | × | コンテンツ層の仕事 |

## Concentricity（角丸の連鎖）

ネストする角丸は同心にする。**内側 radius = 外側 radius − 間隔**:

```css
.outer { border-radius: var(--lg-ref-radius-xl); padding: var(--lg-ref-gap-nav); }
.inner { border-radius: calc(var(--lg-ref-radius-xl) - var(--lg-ref-gap-nav)); }
```

comp 層はこれを calc で強制している（`.lg-nav` → `.lg-nav-pill`、
`.lg-card` → `.lg-card-body`）。新しい部品を作るときも直値でなく連鎖式で書く。

## surface の張り方

- surface はセクション単位で祖先に宣言するのが基本
  （`<section data-lg-surface="media">`）
- ヒーロー画像の上のナビ、記事の上の浮遊ボタンなど、**背景が変わる境界では
  surface も変える**。1ページに light と dark が混在してよい
- スクロールで背景が変わる要素（固定ナビ等）は、区間ごとに surface を
  付け替える（IntersectionObserver で `data-lg-surface` を書き換えるのは合法。
  素材側は変数写像なので即座に追従する）

## 色とアクセント

- ガラス上のテキスト・アイコンは `--lg-ink` のモノクローム。色を持たせない
- アクセント着色（ステンドグラス）は **1画面1箇所**、最重要アクションの背景のみ
  （`.lg-button--primary`）。複数のコントロールに色を配らない
- 背景（コンテンツ層）は自由。ガラスは背景の色を拾って見せる装置と考える

## 屈折が見える背景・見えない背景

屈折はエッジで背景を歪ませて初めて知覚される。**構造のない背景の上では
ガラスは立たない**:

- ○ テキスト・罫線・稜線・写真のディテール・グラデーションの境界
- × 無地・巨大なぼかしブロブ・均質なノイズ

ヒーローでガラスを見せたいなら、背景に構造を仕込むこと。これはスタイリングでは
なくレイアウト設計の問題である。
