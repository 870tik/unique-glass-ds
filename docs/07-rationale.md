# 07 — Rationale: デザイン思考・設計判断の記録

このシステムの主要な設計判断と、その根拠・棄却した代替案の記録（ADR 形式の要約）。
「なぜこうなっているか」を将来の自分・クライアント・AI が再判断できるようにする。
思想の憲法は [00-philosophy.md](00-philosophy.md)。ここはその**判断過程**の側。

## R1. lensing を一次定義にする（blur ではなく）

- **判断**: 素材の中心を `backdrop-filter: blur()` ではなく SVG displacement による
  屈折に置いた
- **根拠**: Apple の公式定義が「旧素材は光を散乱、Liquid Glass は光を屈曲・集光」
  （WWDC25 #219）。blur 基調では既存 glassmorphism との差が出ない
- **棄却案**: WebGL 全面採用（DOM ラスタライズの運用リスクが本質的に高い。KV 限定に格下げ）

## R2. 2層フォールバック（lens / baseline）+ opaque

- **判断**: `backdrop-filter: url()` が Chromium 専用である現実を受け、
  CSS ベースラインを全ブラウザの本体とし、屈折は上乗せにした
- **根拠**: WebKit bug 245510 / Firefox 要望段階。標準化（svgwg #1142)は
  セキュリティ境界が難所で1〜2年での解消見込みなし（2026-09 調査）
- **含意**: **可読性とレイアウトは baseline だけで成立させる**。屈折に機能を
  依存させない

## R3. 適応の単位は surface（ページではなく）

- **判断**: `data-lg-surface` をガラス個体/祖先に宣言する API にした
- **根拠**: 探索プロトタイプ（Pure Lens）はページ単位のシーン切替で適応を
  実装しており、批評で「明暗混在の実 LP を組めない」最大欠落と指摘された。
  可読性・不透明フォールバック・rim 色・primary コントラストの問題が全部
  この1点に合流した
- **棄却案**: 背景ピクセルの実サンプリング（コスト・iframe/CORS 制約・
  スクロール追従の複雑さに対し、宣言的 context で実用上十分）

## R4. 直値ゼロ（single source = DTCG JSON）

- **判断**: 色・数値は tokens.json → 生成 CSS 変数のみ。CSS への直書きは契約違反
- **根拠**: 探索 Dark Lens は rgba リテラル約20個の散在により「テーマとして
  差し替え不能 = システムを名乗れない」と批評された。実際、テーマ化は
  上書き16トークンで完了した（R4 が正しかった証明）
- **運用**: 違反は grep で検出可能。z-index の直値残存も後日この規律で一掃

## R5. ガラス予算制（1ビューポート3枚 + 一時面は予算外）

- **判断**: 希少性を定量ルール化。アプリでは恒常クローム（sidebar+topbar）=1枚
- **根拠**: 公式の "Use Liquid Glass sparingly" を、AI にも人間にも判断委譲できる
  予算という形に翻訳（自動車 HMI の glance-time 予算の借用）。既存 glassmorphism
  キットに欠けていた「意味論」の中核
- **含意**: データテーブルをガラスにしたくなったら設計が間違っている

## R6. gel は変形の物理、追従は 1:1

- **判断**: バネは復帰にのみ使い、入力追従（角度・値・押下開始）は常に即時
- **根拠**: 公式の gel は "moves in tandem with your interaction"（遅延ではなく連動）。
  制作者の品質基準としても入力追従の粘性遅延は不採用。リム光の自律周回も
  「光源は操作に応答する」という公式モデルへの違反として批評で kill された

## R7. Regular / Clear の2相と 35% dim

- **判断**: バリアントは公式の2相のみ。独自の中間相は作らない
- **根拠**: "They should never be mixed" と "dark dimming layer of 35% opacity" は
  数少ない明文数値。忠実性の担保はこういう箇所の遵守に宿る

## R8. コンテンツ層を成果物に含める

- **判断**: Panel / Table / Stat / Banner 等の不透明部品もシステムに同梱
- **根拠**: 二層モデルでは SaaS の主役（読む要素）はガラスにならない。
  ガラス部品だけ配っても「このシステムだけで組み切れる」という成功定義を
  満たせない

## R9. AI 判断手順（SKILL.md）を一級成果物にする

- **判断**: トークン表の再掲ではなくデシジョンツリーを配布物の中心に置く
- **根拠**: 2025-26 の AI-readable DS 潮流の要件（用途命名・description・関連性）と、
  既存キットの欠落（なぜ、の不在）。トークンの $description に判断根拠を
  書く規律もここから

## R10. BRAND からの切り離し

- **判断**: 本システムは Taiki 個人ブランド（BRAND/design-principles.md 原則1 =
  UI 面材へのガラス禁止）の適用対象外の独立プロダクトとする
- **根拠**: 原則との衝突を「例外」でなく「対象外」で解消し、クライアント納品用の
  雛形として無色ニュートラルを既定に。スタジオ色は studio-dark テーマに隔離した

## R11. 独自物質「Prism」への分岐（v2）

- **判断**: Apple 忠実（R= 初期ブリーフ）を分岐し、独自素材 Prism を既定とした。
  (a) 分散を隠さず署名にする（ca 6px・分離比拡大・スペクトラムリム）、
  (b) 観測機器の意匠（spec-tag・mono 計測表記・素材が物性を申告する）
- **根拠**: システムの独自性が「規範の構造」に偏り、視覚の独自性が
  Apple の借景だった。公理体系は「架空の物質の定義」なので、物質そのものを
  差し替えても規律は無傷 — むしろ体系の証明になる
- **互換**: Apple 相当の控えめ光学は theme apple-quiet（5トークン）として保存。
  既定とテーマの関係を v1 と反転させた
- **棄却案**: 見た目だけのテーマ追加（物質の定義に触れない独自化は表層に留まる）

## R12. 応答する光学（v2）

- **判断**: 押下時に屈折・分散パラメータ自体をバネ駆動する（レンズが潰れて
  平らになる物理）。gel（形の変形）に光学の変形を重ねた
- **根拠**: Prism の「光学が主役」という主張を、静的な見た目からモーションへ
  拡張する次の一段。Web のガラス表現で屈折が入力に応答する前例はない。
  公理5「変形の物理」の正統な帰結であり、粘性追従禁止とも矛盾しない
- **実装**: 初回押下時に共有フィルタを要素専有へ複製し、feDisplacementMap の
  scale 3枚を Spring で駆動（キャッシュ共有と両立）。係数はトークン
  `--lg-motion-gel-optics-press`（0.3）
- **棄却案**: falloff の同時アニメ（マップ再生成が毎フレーム必要でコスト過大。
  scale のみで「平らになる」印象は十分成立）

## R13. 生命徴 vital signs（v2）

- **判断**: 「少し生きている」感覚を3機構で導入 — (a) 個体差（変位マップの
  有機ノイズ・4個体プール）、(b) 瞳孔反射（hover で ×0.92 収縮）、
  (c) 注視の呼吸（focus-visible 中のみリム明滅・3.6s）
- **根拠**: 生物性は「アイドルアニメ」ではなく、不完全性（個体差）と
  応答性（反射）でこそ宿る。(a)(b) は公理内。(c) のみ公理4を改定し、
  「注視は相互作用であり、応える光は自律ではない」という一点例外を明文化
- **境界**: 装飾の常時アニメ・視線/カーソル追従・アイドル揺れは引き続き禁止。
  生命徴の追加は R 判断必須。apple-quiet テーマは全生命徴オフ（互換維持）
- **棄却案**: 常時の微呼吸（注視なし）— 公理4の実質的放棄になり、
  「静止しているから、応えた瞬間が生きて見える」という対比構造を壊す

## R14. gel v2 — Squash & Stretch + Follow-through（v2）

- **判断**: gel を均一スケールからアニメーション古典技法へ拡張。
  press = 縦0.90×横1.06 の体積保存 squash、release/hover = ζ0.42 の
  低減衰バネで揺れて到達（プルプル感）。hover で 1.03 に膨らむ
- **根拠**: 「生きている」感覚は生命徴（R13）の知覚下の反応に加え、
  変形の誇張で身体的に伝わる。12原則の Squash & Stretch は
  公理5「変形の物理」の直接の応用であり、禁止事項（追従遅延）に触れない
- **境界**: 揺れるのは目標到達だけ。押下の 1:1 即応・角度追従の即時性は不変。
  apple-quiet テーマでは全て v1 相当に戻る
- **補遺**: 弾性は素材共通の物性として操作可能な塗り部品にも標準搭載
  （chip・pagination・icon-button・select・step）。光学はガラス専権のまま。
  「押せるものだけが応える」が生死の境界

## R15. タイポグラフィの声（v2）

- **判断**: Latin の顔に Space Grotesk（見出し・数値・巨大アウトライン）、
  計測の声に IBM Plex Mono（spec-tag・ラベル・目盛り）を採用し同梱（OFL）
- **根拠**: 物質に人格（Prism）がある一方、文字がシステムフォントの借り声だった。
  幾何学×技術の Grotesk は観測機器の意匠と同族。和文はシステムフォールバックで
  共存（見出しの Latin 部分・数値・ラベルに声が乗る設計）
- **境界**: 本文はシステムのまま（可読性最優先・同梱容量の抑制）。
  フォント追加は woff2 latin subset のみ・合計 100KB 以下を維持

## R16. 観測者効果 — 個性を持たないという個性（v2 最終章）

- **判断**: 「決定的な個性」と「人によって見た目が変わる」を対立させず統合。
  プリズムの物理（見え方は観測者依存）を公理7に昇格し、範囲トークン +
  観測者シードで実装した。二人として同じ画面を見ない
- **根拠**: 無色（公理2）→ 分光（R11）→ 応答（R12）→ 生命徴（R13）と来た
  物語の必然的な終点。個性の所在を「作り手の指紋」から「観測の関係性」へ移す
- **境界**: 揺れるのは分光色相・光源角・呼吸・個体差・**accent（primary）**。
  accent は環境光と同角で回り、背景のうっすらした色と常に同調する（2026-09 改訂 —
  無色コアの primary はブランド色ではなく「その観測者の色」）。状態色
  danger/warning/success の意味は不変（a11y 保護）。既定は fixed（製品の一貫性・QA 再現性）で、
  personal は明示 opt-in
- **棄却案**: accent まで揺らす（ブランド識別の崩壊）/ 常時ランダム
  （シード永続がないと「あなたのプリズム」という愛着が生まれない）
- **補遺（SP 対応）**: hover は SP に存在しないため、観測者差の主経路を
  (a) 環境光の色相 ±40°（装飾背景のみ・開いた瞬間に見える。中身を巻き込まない
  よう背景専用層に filter を隔離）、(b) タップ点灯（`.lg-glass:active` で
  分光リムが点く）へ拡張。分光回転も ±60° に拡大し、一瞥での個体差を成立させた

## R17. 体質 Physique — 形が個人に馴染む（v2）

- **判断**: 動き・光学の2軸 trait（0〜1）で、gel の揺れ・潰れ・呼吸の深さ・
  分散・個体差・リム強度が min/max の間で確定する。trait 0.5 = 現行値
  （完全後方互換）。ソースは (1) ホストが渡す抽象 trait（data-lg-trait-*）
  (2) 端末内の操作テンポ学習（personal のみ・±0.08・翌訪問反映）(3) 深夜は
  光学が静かに（端末時計のみ）(4) reduced-motion は motion=0 に固定
- **プライバシー境界（重要）**: DS は生の個人データ — 検索履歴・他サービスの
  利用状況・属性そのもの — を**読まない・受けない・保存しない**。受けるのは
  抽象化された 0〜1 の trait のみで、その導出はホスト製品の責務。端末内学習は
  localStorage 完結・リセット可能。「生きている素材」を「監視する素材」に
  しないための恒久条項
- **棄却案**: 行動トラッキング基盤との連携（技術的にも DS の責務外、
  思想的にも生命徴の魅力を不気味さに変える）/ セッション中のリアルタイム変化
  （gel 定数はキャッシュされるため不安定。「体質は一晩で変わる」方が生物として自然）

## R18. 環境信号 — 現実に応答する素材（v2）

- **判断**: 素材が「観測者」（R16/R17）に続き「置かれた環境」にも応答する4信号を導入 —
  (a) 太陽同期（端末時刻→太陽方位の近似が光源基準角になる。朝は右から、夕は左から）、
  (b) 傾き応答（DeviceOrientation で光源が端末の傾きに 1:1 追従 = SP の hover 代替）、
  (c) バッテリー=元気（残量 20% 以下・非充電で呼吸半減・点灯減・押下光学が浅く。
  疲労の身体性と描画コスト削減が一致する）、
  (d) 懐き（訪問日数で生命徴が開く。初訪は人見知り、8日で全開。personal のみ）
- **根拠**: 公理4「光は応答である」の応答先を操作から環境へ拡張する正統な一段。
  すべて**端末内で完結**し、R17 のプライバシー境界の内側に収まる
  （ネットワーク送信なし・生データ保存なし・傾きの iOS 許諾は明示ジェスチャー経由）
- **境界**: 動かすのは光源角・呼吸・点灯・押下光学のみ。レイアウト・コントラスト・
  状態色・ガラス予算は不変レイヤーのまま。`--lg-signals-*` で個別無効化、
  apple-quiet テーマは全オフ。fixed モードでは懐きは常に全開（QA 決定性）
- **属性の扱い（補遺）**: 年齢・職業などの属性で変えたい要求には、DS 側 API を
  作らず**ホスト側写像**で応える（実演: showcase/index.html のペルソナドック — 26歳
  モーションデザイナー m0.80 / 52歳会計士 m0.23 / 71歳書道家 m0.01）。属性は「初期値の仮説」であり本人設定が常に上書き。
  性別・婚姻歴の直結はステレオタイプ化のため非推奨と明文化
- **棄却案**: 天気 API 連携（ネットワーク依存 = 境界の外。ホストが渡すなら trait 経由）/
  マイク・カメラ由来の推定（生命徴の魅力を監視の不気味さに反転させる）/
  位置情報による太陽の精密化（許諾ダイアログのコストに対し近似で十分）
